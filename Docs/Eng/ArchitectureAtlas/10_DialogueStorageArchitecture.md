# Dialogue Storage Architecture

> Version: 2.0
> Last Updated: 18-07-2026

---

# Purpose

Определить единую архитектуру хранения диалогов проекта.

Система ориентирована на Story-Rich RPG / Visual Novel, где большинство диалогов являются линейными, а нелинейность реализуется через локальные точки выбора.

Архитектура должна поддерживать постепенное развитие проекта без изменения Runtime-системы.

---

# Architecture Name

**Node-Based Dialogue Architecture**

Google Sheets → JSON → Dialogue Objects → Dialogue Database

A node-based dialogue pipeline designed for incremental evolution from linear narratives to complex RPG dialogue systems.

---

# General Concept

Диалоги создаются в Google Sheets.

Google Sheets является единственным источником данных (**Source of Truth**).

Во время импорта данные автоматически экспортируются в JSON.

После загрузки JSON преобразуется в объектную модель.

Во время выполнения игры система работает исключительно с объектами, а не с JSON.

```
Google Sheets
        ↓
 Google Sheets → JSON
        ↓
     JSON Files
        ↓
 Dialogue Importer
        ↓
 Dialogue Objects
        ↓
 Dialogue Database
        ↓
 Dialogue Runtime
```

---

# Design Goals

Система должна:

- быть удобной для сценаристов;
- поддерживать совместную работу;
- поддерживать большие объемы текста;
- легко храниться в Git;
- поддерживать линейные диалоги;
- поддерживать локальные ветвления;
- обеспечивать быстрый доступ к данным;
- иметь возможность развития без изменения общей архитектуры.

---

# Core Principle

Диалог представляет собой набор связанных между собой узлов (**Dialogue Nodes**).

Каждый узел имеет уникальный идентификатор (**ID**).

Связь между узлами осуществляется исключительно через ID.

Даже полностью линейный диалог рассматривается как последовательность связанных узлов.

---

# Dialogue Structure

Базовый сценарий выглядит как линейная последовательность.

```
1
↓

2
↓

3
↓

4
↓

5
```

Если явно не указан другой переход, выполнение продолжается к следующему узлу.

---

# Branching Model

Ветвления являются локальными.

```
          Choice

         /      \

       30        50

         \      /

          80
```

Все переходы выполняются по ID.

Диалог рассматривается не как дерево, а как граф связанных между собой узлов.

---

# Data Pipeline

Архитектура разделена на несколько независимых этапов.

## Google Sheets

Используется исключительно для создания и редактирования сценариев.

Является единственным источником данных проекта.

---

## JSON

Является промежуточным форматом обмена данными.

Используется только для импорта.

JSON никогда не редактируется вручную.

---

## Dialogue Importer

Отвечает за загрузку JSON.

Преобразует сериализованные данные в объектную модель игры.

Также выполняет проверки корректности данных перед созданием объектов.

---

## Dialogue Objects

Представляют собой рабочую объектную модель диалогов.

Каждый Dialogue Node существует как полноценный объект в памяти.

Runtime работает только с этими объектами.

---

## Dialogue Database

Является центральным хранилищем всех загруженных диалогов.

Хранит данные в двух представлениях:

- List — для хранения полного набора объектов и последовательного перебора.
- Dictionary — для мгновенного доступа к узлу по ID.

После загрузки вся игровая логика получает данные исключительно через Dialogue Database.

---

# Source of Truth

Все изменения сценария выполняются исключительно в Google Sheets.

JSON является промежуточным форматом.

Dialogue Objects создаются автоматически.

Dialogue Database полностью строится автоматически.

Ручное изменение промежуточных данных не допускается.

---

# Import Responsibilities

Импортер обязан:

- загрузить JSON;
- преобразовать данные в объекты;
- выполнить валидацию;
- сформировать Dialogue Database;
- сообщить обо всех найденных ошибках.

---

# Validation

Во время импорта рекомендуется проверять:

- уникальность ID;
- существование всех Target ID;
- отсутствие битых ссылок;
- корректность структуры данных;
- отсутствие поврежденных записей.

При наличии ошибок Dialogue Database не должна создаваться.

---

# Runtime Principle

Dialogue Runtime никогда не работает напрямую с JSON.

После загрузки JSON полностью преобразуется в объектную модель.

С этого момента игровая логика взаимодействует исключительно с Dialogue Objects через Dialogue Database.

Таким образом:

```
Google Sheets

↓

JSON

↓

Dialogue Objects

↓

Dialogue Database

↓

Runtime
```

JSON используется только как промежуточный формат хранения и импорта.

---

# Scalability

По мере роста проекта допускается разделение данных:

- по главам;
- по персонажам;
- по локациям;
- по квестам;
- по DLC;
- по эпизодам.

Это не влияет на игровую систему.

---

# Future Evolution

Архитектура изначально проектируется как расширяемая.

По мере развития проекта Dialogue Node может получать новые свойства.

Например:

- Choices
- Conditions
- Variables
- Actions
- Skill Checks
- Events
- Camera
- Animation
- Portrait
- Voice
- Music
- Sound Effects
- Localization
- Metadata
- Custom Node Types

Расширение структуры Dialogue Node не должно требовать изменения архитектуры хранения данных.

---

# Editor Evolution

На ранних этапах используется Google Sheets.

При необходимости редактор может быть заменен.

```
Google Sheets

↓

Google Sheets + Validation

↓

Google Sheets + Unity Tools

↓

Dedicated Dialogue Editor

↓

Graph Editor
```

Dialogue Runtime, Dialogue Objects и Dialogue Database при этом остаются неизменными.

Меняется исключительно инструмент создания контента.

---

# Long-Term Vision

Даже при переходе к сложной RPG-системе с большим количеством:

- условий;
- игровых переменных;
- проверок навыков;
- внутренних монологов;
- сложных ветвлений;
- событий;
- повествовательных механик,

архитектура остается прежней.

Диалог продолжает представлять собой граф связанных Dialogue Nodes.

Изменяется только объем информации, содержащейся внутри каждого узла.

## Main Advantages

- Google Sheets является единым источником данных.
- JSON используется только как промежуточный формат.
- Runtime полностью независим от формата хранения.
- Dialogue Objects являются рабочей моделью данных.
- Dialogue Database обеспечивает быстрый доступ ко всем узлам.
- Простая работа сценаристов.
- Удобная совместная работа команды.
- Хорошая интеграция с Git.
- Автоматическая проверка данных.
- Высокая производительность благодаря объектной модели.
- Простое масштабирование.
- Возможность постепенного развития системы без изменения общей архитектуры.
