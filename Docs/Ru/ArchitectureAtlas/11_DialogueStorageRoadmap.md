# Dialogue System Evolution Roadmap

> Version: 1.
> Last Updated: 15-07-2026

---

# Purpose

Документ описывает предполагаемое развитие архитектуры хранения диалогов.

Он не определяет реализацию.

Он показывает направление эволюции системы.

---

# Stage 1 — Linear Dialogue

Минимальная рабочая версия.

Поддерживает:

- линейные реплики;
- последовательное выполнение;
- переход к следующему узлу.

Пример данных:

```
ID
Speaker
Text
NextID
```

---

# Stage 2 — Dialogue Choices

Добавляется возможность выбора игроком.

Поддерживает:

- несколько вариантов ответа;
- переходы к разным узлам.

Пример:

```
Choices

•

Text

TargetID
```

---

# Stage 3 — Dialogue Conditions

Появляются условия отображения узлов и вариантов ответа.

Примеры данных:

```
QuestCompleted

Flag

Variable

HasItem

Relationship
```

### Примеры игровых ситуаций

**QuestCompleted**

Игрок завершил квест "Спасти кузнеца".

После этого NPC благодарит героя и открывает новую сюжетную ветку.

---

**Flag**

Во время предыдущего разговора игрок соврал персонажу.

Устанавливается флаг `PlayerLied = true`.

При следующей встрече NPC вспоминает ложь и меняет отношение к игроку.

---

**Variable**

Игрок накопил достаточно репутации.

Если `Reputation >= 50`, становятся доступны новые варианты диалога.

---

**HasItem**

У игрока есть древний амулет.

NPC замечает его и начинает совершенно другой разговор.

Без амулета этот диалог никогда не появится.

---

**Relationship**

Отношения с персонажем достигли высокого уровня.

Теперь вместо официального общения открываются более личные реплики.

---

# Stage 4 — Dialogue Actions

После выполнения узла могут запускаться игровые действия.

Примеры данных:

```
SetFlag

GiveItem

RemoveItem

StartQuest

FinishQuest

AddMoney

RemoveMoney
```

### Примеры игровых ситуаций

**SetFlag**

После признания в преступлении устанавливается:

```
ConfessedToGuard = true
```

Позже этот факт может изменить другие диалоги.

---

**GiveItem**

После разговора торговец вручает игроку старый ключ.

Ключ сразу появляется в инвентаре.

---

**RemoveItem**

Игрок передает лекарство врачу.

Предмет удаляется из инвентаря.

---

**StartQuest**

Во время разговора капитан просит найти пропавшего разведчика.

После окончания диалога автоматически начинается новый квест.

---

**FinishQuest**

Игрок сообщает о выполненной работе.

Квест завершается, выдаются награды и открываются новые события.

---

**AddMoney**

За успешно выполненное поручение игрок получает награду.

Баланс увеличивается.

---

**RemoveMoney**

Игрок оплачивает ночлег в гостинице.

Стоимость проживания автоматически списывается.

---

# Stage 5 — Skill Checks

Добавляются проверки характеристик персонажа.

Пример данных:

```
Skill

Difficulty

Success

Failure
```

### Примеры игровых ситуаций

**Persuasion**

Игрок пытается убедить стражника пропустить его.

При успехе открывается проход.

При провале приходится искать другой путь.

---

**Intelligence**

Игрок изучает древнюю надпись.

Высокий интеллект позволяет правильно перевести текст.

При неудаче смысл остается неизвестным.

---

**Strength**

Необходимо поднять тяжелую каменную плиту.

Сильный персонаж справляется самостоятельно.

Остальным придется искать обходной путь.

---

**Luck**

Игрок пытается найти тайник среди мусора.

При успешной проверке обнаруживается редкий предмет.

---

# Stage 6 — Variables

Появляется полноценная работа с игровыми переменными.

Пример данных:

```
bool

int

float

string
```

Поддерживаются:

- проверки;
- изменение;
- сравнение.

### Примеры игровых ситуаций

**bool**

```
HasSeenSecretRoom
```

После первого посещения секретной комнаты повторный диалог становится другим.

---

**int**

```
Reputation = 82
```

Чем выше репутация, тем больше NPC доверяют игроку.

---

**float**

```
Sanity = 34.5
```

Низкий уровень рассудка открывает необычные реплики и внутренние монологи.

---

**string**

```
Guild = "Alchemists"
```

Персонажи по-разному реагируют в зависимости от выбранной гильдии.

---

# Stage 7 — Advanced Presentation

Узел начинает управлять визуальной и аудиоподачей сцены.

Пример данных:

```
Portrait

Emotion

Animation

Camera

Music

SFX

Voice

Delay
```

### Примеры игровых ситуаций

**Portrait**

Во время разговора портрет персонажа меняется на крупный план.

Это подчеркивает важность реплики.

---

**Emotion**

После плохих новостей выражение лица NPC меняется с улыбки на грусть.

---

**Animation**

Во время диалога персонаж достает оружие или отворачивается от игрока.

---

**Camera**

В момент признания камера плавно приближается к лицу персонажа.

Это усиливает эмоциональный эффект сцены.

---

**Music**

Во время разговора начинается тревожная музыкальная тема.

Игрок понимает, что ситуация становится опасной.

---

**SFX**

После открытия двери воспроизводится характерный звук тяжелого механизма.

---

**Voice**

Для ключевой реплики проигрывается заранее записанная озвучка.

---

**Delay**

После неожиданной новости возникает двухсекундная пауза.

Только затем появляется следующая реплика, создавая драматический эффект.

---

# Stage 8 — Advanced Narrative

Добавляются сложные повествовательные механики.

Например:

- внутренние мысли;
- скрытые реплики;
- пассивные проверки;
- комментарии спутников;
- автоматические вставки.

---

# Stage 9 — Dialogue Editor

Если Excel перестает быть удобным,

возможен переход к специализированному редактору.

Варианты:

- Unity Editor;
- Graph Editor;
- собственный инструмент.

Runtime при этом не изменяется.

---

# Stage 10 — Mature Dialogue System

Финальная архитектура представляет собой граф узлов.

Каждый узел может содержать:

```
ID

Speaker

Text

Choices

Conditions

Actions

Variables

SkillChecks

Events

Camera

Animation

Audio

Portrait

Tags

Localization

Metadata
```

---

# Evolution Principle

Архитектура развивается не путем замены системы хранения,

а путем постепенного расширения возможностей узла.

```
Node

↓

Node + Choices

↓

Node + Conditions

↓

Node + Actions

↓

Node + Skill Checks

↓

Node + Presentation

↓

Node + Narrative Systems
```

Таким образом сохраняется совместимость между ранними и поздними версиями проекта.
